# Часть 2. Подготовка данных и CLI-утилита препроцессинга

Утилита собирает файлы каталога в один массив NumPy и проверяет окружение.

## Структура

| Файл | Назначение |
|------|------------|
| `app/cli.py` | подкоманды `prepare` и `doctor`, разбор аргументов через `argparse` |
| `app/config.py` | настройки из переменных окружения, `.env` и аргументов командной строки |
| `app/scanner.py` | обход каталога через `pathlib`, чтение изображений и таблиц, сборка массива |
| `app/logging_config.py` | логирование в консоль и файл |

## Запуск

```bash
cd part2_prepare

# собрать массив из изображений
python -m app.cli prepare --path ../data/input/images --ext .png \
    --output images_dataset.npy

# то же с изменением размера и отладочным логом
python -m app.cli prepare --path ../data/input/images --ext .png .jpg \
    --resize 32x32 --output images_32.npy --log-level DEBUG

# собрать массив из CSV-таблиц
python -m app.cli prepare --path ../data/input/tables --ext .csv \
    --output tables_dataset.npy

# проверить окружение
python -m app.cli doctor
```

Относительный путь в `--output` отсчитывается от каталога вывода
(`NN_OUTPUT_DIR`), поэтому результат не зависит от текущего каталога.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|------------|--------------|-------|
| `NN_DATA_PATH` | `data/input` | каталог с данными |
| `NN_OUTPUT_DIR` | `data/output` | каталог результатов |
| `NN_LOG_LEVEL` | `INFO` | уровень логирования |
| `NN_IMAGE_SIZE` | `64x64` | размер, к которому приводятся изображения |
| `NN_EXTENSIONS` | `.png,.jpg,.jpeg,.bmp,.tiff` | расширения по умолчанию |
| `NN_OUTPUT_FILE` | `dataset.npy` | имя файла результата |

Значения из переменных окружения перекрываются аргументами CLI, а файл
`.env` (если установлен `python-dotenv`) загружается до чтения окружения.

## Что делает `prepare`

1. Рекурсивно обходит каталог (`Path.rglob`).
2. Читает изображения через PIL, приводит к нужному размеру и делит на 255.
3. Читает числовые CSV, при необходимости пропуская строку заголовка.
4. Проверяет, что все файлы дают массивы одинаковой формы.
5. Сохраняет результат в `.npy` и рядом кладёт `.json` с описанием набора.
6. Печатает статистику: число файлов, форму массива, минимум и максимум,
   время обработки и размер файла.

## Что проверяет `doctor`

- версию Python и платформу;
- наличие библиотек `numpy`, `PIL`, `dotenv`, `matplotlib`, `tensorflow`, `torch`;
- доступность CUDA через `nvidia-smi` (вызов через `subprocess.run`);
- свободное место на диске (`shutil.disk_usage`) и права на запись;
- текущий рабочий каталог.
